## LAN Commander v1.1.0

`seguridad` · `agente` · `control-center` · `instaladores` · `correcciones` · `windows-arm64` · `appimage`

Versión centrada en endurecer el agente y en que actualizar no cueste datos. Incluye por primera vez instalador para **Windows ARM64** y **AppImage** para Linux.

### Descargas

| Archivo | Para qué sirve |
|---|---|
| `LAN-Commander-1.1.0-windows-amd64-setup.exe` | Control Center para Windows x64 |
| `LAN-Commander-1.1.0-windows-arm64-setup.exe` | Control Center para Windows ARM64 |
| `LAN-Commander-1.1.0-linux-x86_64.AppImage` | Control Center para Linux x86_64 |
| `lan-commander-agent-1.1.0-windows-amd64.zip` / `-windows-arm64.zip` | Agente + instalador `install-agent.ps1` |
| `lan-commander-agent-1.1.0-linux-amd64.tar.gz` / `-linux-arm64.tar.gz` | Agente + instalador `install-agent.sh` |
| `SHA256SUMS.txt` | Sumas SHA-256 de todos los archivos |

Los ejecutables **no están firmados**: Windows SmartScreen puede avisar al ejecutarlos. Comprueba las sumas con `SHA256SUMS.txt`.

El AppImage usa WebKitGTK del sistema (`libwebkit2gtk-4.1` y `libgtk-3`); en Debian/Ubuntu: `sudo apt install libwebkit2gtk-4.1-0 libgtk-3-0`.

### Actualizar sin perder datos

- Los datos del Control Center (sesiones, auditoría, scripts) están en `%APPDATA%\LAN Commander` (Windows) o `~/.config/LAN Commander` (Linux), **fuera** de la carpeta de instalación y del AppImage. Instalar encima, actualizar o desinstalar no los toca.
- Al arrancar por primera vez, esta versión copia `lan-commander.db` y `audit.db` a `*.db.bak-1.1.0` **antes** de migrar el esquema (se conservan las 5 copias más recientes). Para volver atrás, cierra la aplicación y renombra la copia.
- El instalador del agente conserva el token existente al reinstalar; no hace falta volver a cargarlo en el Control Center.
- El CI instala, actualiza y desinstala el paquete de Windows comprobando que los datos del usuario siguen intactos, y arranca el AppImage sobre una base de datos de la versión anterior comprobando que se migra y se respalda.

### Novedades

- **Instalador para Windows ARM64**, probado de forma nativa en un runner ARM64.
- **AppImage** para Linux x86_64.
- **Auditoría local en el agente** (`--audit-log`): una línea JSON por evento (autenticaciones, comandos, listados, transferencias, capturas), con rotación a 5 MB.
- **Listados de carpetas completos**: `list_dir` admite paginación (`offset`/`limit`) y devuelve el total real; el Control Center lee hasta 5000 entradas y avisa cuando la lista es parcial.
- **Reconexión de sesiones guardadas** desde el Control Center, Multi-Exec mejorado y dashboard con todos los discos.
- El agente acepta `--auth-token-file` y la variable `LAN_COMMANDER_AUTH_TOKEN`.

### Seguridad

- El token **ya no queda en los argumentos del servicio**: los instaladores lo guardan en un archivo de acceso restringido (`%ProgramData%\LAN Commander Agent\agent.token` o `/etc/lan-commander/agent.token`) y el servicio lo lee con `--auth-token-file`.
- Una conexión que no se autentica en 15 s se cierra, aunque envíe `keep_alive`.
- Límite de 16 conexiones simultáneas por IP; una IP con 20 autenticaciones fallidas por minuto queda bloqueada un minuto (responde 429).
- Si un cliente no lee sus respuestas y la cola de envío se llena, el agente cierra esa conexión en lugar de descartar mensajes en silencio.
- `--tls-cert` y `--tls-key` deben indicarse juntos; antes, uno solo hacía caer el agente a `ws://` sin avisar.
- El Control Center ya no entrega el token de los agentes al frontend.

### Correcciones

- Los comandos con comillas dobles en Windows (`cmd.exe`) llegaban mal escapados (`echo "hola"` imprimía `\"hola\"`).
- Un comando más largo que el tiempo de espera de lectura perdía su resultado y cerraba la conexión.
- El timeout de un comando ahora termina todo el árbol de procesos, no solo el shell.
- Un comando con más de 1 MB de salida se reportaba como fallo.
- Nombres de archivo con `..` dentro (`backup..old.txt`) se rechazaban sin motivo; solo se rechaza `..` como elemento completo de la ruta.
- La interfaz dejaba de responder mientras se conectaba a un equipo inalcanzable.
- Cancelar una subida dejaba un `.part` huérfano en el equipo remoto.
- La versión del agente estaba repetida en tres sitios; ahora hay una sola.

### Cambios que conviene conocer

- **Firewall de Windows:** el instalador del agente abre el puerto solo en los perfiles *Dominio* y *Privado*. Si la red del equipo está clasificada como *Pública*, reinstala con `-FirewallProfile Domain,Private,Public`.
- **Instalador de Windows (Control Center):** se instala en `Program Files\LAN Commander` y el acceso directo se llama «LAN Commander».
- **Protocolo:** los campos nuevos de `list_dir` son aditivos; Control Center y agentes de versiones distintas siguen entendiéndose (un agente antiguo devuelve una sola página).
- Si actualizas un agente instalado con la versión anterior, vuelve a ejecutar el instalador: así el token pasa del argumento del servicio a su archivo y se activa la auditoría. Como la versión anterior guardaba el token en los argumentos del servicio, el instalador generará uno nuevo salvo que indiques el tuyo con `-AuthToken` / `--auth-token`.

### Limitaciones conocidas

- El tráfico sigue sin cifrar por defecto (`ws://`); TLS es opcional y los instaladores no lo configuran.
- La captura de pantalla puede fallar cuando el agente corre como servicio sin sesión gráfica.
- El token es compartido: no hay identidad por operador ni rotación automática. El campo `user` de la auditoría local es el que declara el cliente.
- Los ejecutables no están firmados.
